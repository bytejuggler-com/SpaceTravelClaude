Introduction

A trip in the spirit of the demoscene

Space Travel is a five-minute real-time journey in the tradition of the Amiga and PC demos of the late 80s and 90s: a sequence of effects cut to the music, where the coolness of the effect and the cleverness behind it matter more than physical accuracy.

It opens like a 1990 cracktro — copper bars, a chrome logo, a sine scroller — then leaves the screen behind: parallax stars, a nebula of dust pillars, the jump to hyperspace, a giant star, an asteroid chase, a ringed planet and a canyon on one of its moons, a fleet of capital ships, a supernova, a wormhole into another galaxy and the black hole at its heart, before the credits roll on a cloud of vector balls.

Every pixel is computed at run time. There are no textures, models or samples on disk: rock and ship meshes are generated at start-up, noise volumes are built by a compute shader, the font is drawn in code and even the soundtrack is a ProTracker module synthesized in memory. Each scene reacts to the music through a beat grid and per-instrument note timing.

This book walks through the scenes as images first, then opens the hood: for each effect, the idea behind it and the algorithm in high-level pseudo-code, close to the GLSL that actually runs.

Pure functions of time

No scene accumulates state from frame to frame. Anything that moves — a ship on its path, a star in its orbit, a camera rolling into hyperspace — is computed from the current time, integrating speed curves when needed. That single rule makes the whole demo scrubbable: it can be paused, rewound, looped on one scene or captured at any beat, which is how the images of this book were made.

Music and sync

The soundtrack is a tracker module played by libopenmpt. At load time the module is played through once, silently, to record the exact time of every row and note-on. Scenes then ask for seconds since the last kick or since the last snare — again a pure function of time — and turn it into flashes, pulses and flares.

Building blocks

  • Fullscreen passes for anything raymarched or raytraced (most scenes).
  • Procedural geometry: quads and points built in the vertex shader from gl_VertexID.
  • Mesh renderer: procedural meshes, GPU instancing from one storage buffer, cascaded soft shadows.
  • Noise volume: a 128³ tileable texture generated by a compute shader, the raw material of every cloud.
// one frame of the demo
frame(t):
    playhead = timeline.at(t mod timeline.length)
    sync     = syncTrack.evaluate(songTime(t) − latency)
               // beat phase, seconds since each note-on

    hdrA = render(playhead.scene, playhead.localTime, sync)
    if playhead.transitioning:
        hdrB = render(playhead.previous, previousLocalTime, sync)
        hdr  = transitionShader(hdrB, hdrA, playhead.blend)
    else:
        hdr  = hdrA

    // post chain
    bloom  = downsample13(threshold(hdr)) … 6 mips
    bloom  = tentUpsample(mips) accumulated back up
    color  = chromaticAberration(hdr) + bloom · intensity
    color  = ACES(color · exposure) · vignette
    screen = sRGB(color) + grain

// a scene is a pure function of its context
interface Scene:
    init(resources)               // meshes, shaders, buffers
    render(context, hdrTarget)    // context = time, beat, params
    imgui()                       // live tweakables in dev builds
THE ENGINE
00

Tools of the trade

The dev overlay

Development builds carry a Dear ImGui overlay on top of the demo. It shows frame timings measured with GPU timer queries, a time slider that scrubs the whole demo, the timeline with the active entry and its transition, every shader program with its compile status, and per-scene sliders. Timeline parameters are supported only where the scene explicitly reads them; their keys can differ from slider labels, and some controls are UI-only. For example, corona supports orbit, scale and snare as timeline keys.

Hot reload

Shaders are read straight from the source tree with a small #include preprocessor. When a file changes on disk the program is rebuilt; if the new version fails to compile the old one keeps running and the error, mapped back to file and line, appears in the overlay. The timeline file reloads the same way, so scene order, lengths and transitions can be edited while the music plays.

Capture

SpaceTravel --capture frame.png --time 170.88 renders the frame at that instant and exits — the pure-time rule makes captures repeatable with the same settings. A distribution build disables the overlay and hot reload, retains capture support, and links statically into a single executable.

INTRO
01

Intro · one fragment shader

One shader, seven copper bars and an 8×8 font drawn in source code.

The whole scene is a single fullscreen shader. Text comes from a built-in 8×8 bitmap font, designed as rows of X and . in the source code and uploaded as a tiny texture atlas; the strings live in a second integer texture, one line per row, so the shader can look up any glyph pixel directly.

  • Copper bars: seven bars on sine paths; the nearest one covering the pixel wins, its depth darkening it, a squared profile giving the rounded tube and a thin specular line. They flash on the kick.
  • Chrome logo: each font pixel becomes a bevelled tile; colour is a sky-to-horizon chrome gradient by glyph row, a diagonal shine sweeps across, rows wobble with the beat. It drops in with a bounce.
  • Sine scroller: two summed sines bend the text per column; the water below mirrors it with a rippled lookup.
for each pixel:
    color = gradient() + twoLayersOfDriftingStars()

    // copper bars: keep the nearest bar covering this row
    for i in 0..6:
        phase  = t·speed + i·0.45
        center = 0.6 + 0.24·sin(phase);  depth = cos(phase)
        d = |y − center| / thickness
        if d < 1 and depth > nearest:
            bar = palette(i) · (0.25 + 1.4·(1 − d²)) · depthShade
                  + specular(1 − d²)¹⁶ ;  bar ·= 1 + kickPulse

    // logo: font pixel → bevelled tile
    q   = (pixel − origin(bounce(t))) / blockSize
    q.x += sin(row·0.7 + t·2.5) · wobble
    if fontTexel(text, floor(q)):
        color = chrome(row) · bevel(fract(q)) + shineBand(q, t)

    // sine scroller and its reflection
    column = x/block + t·speed
    yText  = y/block − (2.5·sin(column·0.04 + 2t) + 1.5·sin(…))
    if y < waterline: lookup mirrored, x += ripple(y, t), tint blue
Tunables: scroll speedlogo wobblecopper speedkick instrument

Parallax stars

The classic horizontal starfield in six depth layers, and a banded gas giant drifting between them.
PARALLAX STARS
02

Parallax stars · geometry from gl_VertexID

No vertex buffers: a star is six vertices and a hash.

No vertex buffer is involved: one draw call of 6 × stars vertices, and the vertex shader builds each star's quad from its index. Stars are grouped by layer so far and near layers can be drawn in two calls, with the planet in between.

  • Parallax: speed and size grow with layer depth; positions wrap with fract().
  • Motion streaks: each quad is stretched along the motion by the distance covered in 1/60 s, and its brightness spread over the streak.
  • Acceleration is a speed curve integrated on the CPU — never accumulated per frame — so the scene stays scrubbable.
  • Gas giant: a sphere shaded per pixel, with bands from latitude plus 3D fbm turbulence, storms, limb darkening and a blue rim, composited with premultiplied alpha.
// CPU, once per frame
travel = ∫₀ᵗ speed(τ) dτ        // speed rises over the last quarter

// vertex shader, star k (6 vertices per quad)
layer    = k / starsPerLayer;     depth = (layer + 1) / layers
parallax = mix(0.06, 1.0, depth²)
x        = fract(hash(k) − travel·parallax) · span − span/2
radius   = mix(0.7, 2.6, depth) px
streak   = speed · parallax · width / 60 / 2 px
quad     = center ± (radius·2 + streak, radius·2)
color    = tint(hash) · mix(0.25, 3, depth²) · twinkle / (1 + streak·0.3)

// fragment: capsule-shaped gaussian
d = max(|local.x| − streak, 0)² + local.y²
out = color · exp(−1.5 d)              // additive blending

// planet, fullscreen with premultiplied alpha
center = (rightEdge − travel · ½ width, −0.38)   // between far and near layers
n     = sphereNormal(pixel)
bands = sin(latitude·14 + fbm(rotate(n, t)·3)·4)
color = palette(bands) · (0.015 + 1.5·max(n·L, 0)) · limb + rimGlow
Tunables: speedboostdensityplanet

03

Nebula crossing

Towering pillars of dust, sculpted and backlit by a cluster of young stars — fully raymarched volume.
NEBULA CROSSING
03

Nebula · volumetric light

A participating medium marched at half resolution. The pillars are a signed distance — bent, tapering columns with rounded heads — eroded by the noise volume, so their edges break into wisps. Glowing gas fills the space behind them.

  • Self-shadowing: at every sample a short march toward the cluster accumulates dust; that is what carves the light shafts and darkens the pillars' cores.
  • Henyey–Greenstein forward scattering lights the edges when looking toward the light.
  • Energy-conserving integration: each step adds S·(1−e−σΔt)/σ, exact for constant σ and S within that step. Varying density and lighting still cause sampling error.
  • Hubble palette: gas glows teal near the cluster and gold further out.
  • Sky and cluster glow are added at full resolution, dimmed by the volume's transmittance.
for each pixel (½ resolution):
    T = 1;  L = 0;  t = jitter(pixel)·Δt
    repeat N steps:
        p    = ro + rd·t
        dust = clamp(−0.12 · (pillarSDF(p)
                         + 30·(noise(p·0.011) − ½)
                         − 14·(worley(p·0.029) − ½)), 0, 1)
        gas  = cloud(noise(p·0.003)) // behind the pillars only
        σ    = dust·σ_dust + gas·σ_gas

        // how much of the cluster light reaches p
        lit  = exp(−Σk=1..6 dust(p + ℓ·k·s) · s · σ_dust)
        S    = light · lit · falloff(|cluster − p|) · HG(rd·ℓ, g)
               · (dust·albedo + gas·albedo_gas)
             + gasColor(p) · gas · emission
             + rim · dust(1 − dust) · lit      // ionisation fronts

        L += T · S · (1 − e^(−σΔt)) / σ
        T ·= e^(−σΔt);   stop if T < 0.02
    output (L, 1 − T)

composite: (stars + clusterGlow) · T + L
Tunables: stepslight stepsdustgasscatterrimvolume scale

Warp

Sixty thousand stars stretch into streaks as the camera rolls into a hyperspace tunnel.
WARP
04

Warp · motion blur as an effect

Streaks approximate motion blur using speed, shutter time and perspective.

The stars fill a hollow cylinder around the view axis and wrap in depth. Nothing is simulated: a star's position is a pure function of the distance travelled, itself the integral of a speed curve that ramps from cruise to forty times faster.

  • Streaks approximate motion blur: each tail uses current speed × shutter time, with the same roll as the head. Faster means longer, with perspective, without reconstructing the earlier camera pose.
  • Brightness falls with distance and is divided by streak length — long streaks keep their energy.
  • The tunnel behind is noise in polar coordinates: depth = 1/r, high angular frequency against low depth frequency makes radial streaks. It fades in with the hyperspace factor; the stars shift blue.
  • The roll angle is also integrated, so the spin accelerates smoothly.
// CPU
speed(t)  = cruise + (top − cruise) · smoothstep(0.3, 0.97, t/T)³
travel    = ∫ speed,   roll = ∫ rollRate,   hyper = smoothstep(0.55, 1, t/T)

// vertex shader, star k
angle, r², z0 = hash(k)
xy   = rotate(roll) · (cos angle, sin angle) · r
z    = mod(z0·D − travel, D) + near
head = xy / z · focal
tail = xy / (z + speed·shutter) · focal
quad = from tail − axis·w  to  head + axis·w,  width w = max(0.01/z, 1px)
color = tint(hash) → blue(hyper) · (1.2/z) · fadeIn(z) / (1 + 0.12·len/w)

// tunnel, fullscreen behind the stars
r     = |p|,  dir = p / r
depth = 0.25/r + travel·0.04
n     = fbm(vec3(dir·5, depth·0.6))
color = mix(blue, violet, n) · smoothstep(.45, .85, n) · hyper
      + vanishingGlow(r) · hyper

Giant star

GIANT STAR
05

Giant star · surface, corona, prominences

The star is traced at half resolution and composited over a full-resolution celestial sphere of stars (one of the shared building blocks: stars live in 3D cells around the camera and are never clipped at cell borders).

  • Surface: three fbm fields warp the lookup of a finer one — domain warping — for boiling granulation; fine cells on top, large dark spots, and limb darkening that makes the disc read as a sphere.
  • Corona: evaluated at the ray's closest approach to the star. Shifting the noise domain by (height − time) stretches it into streamers that flow outward forever.
  • Prominences: five plasma arcs, each a torus segment standing on the surface in its own frame, raymarched as glowing tubes and turning with the star.
  • The camera orbits with a slow approach; corona flares on the snare.
// surface at normal n (star frame)
warp  = (fbm(p·3 + t·k₁), fbm(p·3 + o₂ − t·k₂), fbm(p·3 + o₃ + t·k₃))
gran  = fbm(p·9 + warp·2.2 + t·0.04)
heat  = (0.75·gran + 0.25·valueNoise(p·30 + warp·4)) · (1 − 0.85·spots(p))
color = ramp(red → orange → white, heat) · (0.3 + 0.7·μ^0.55)

// corona: one sample per ray, at its closest approach
c      = ro + rd·max(−ro·rd, 0);   h = |c| − 1
flames = fbm(dir(c)·5 + (h − 0.12t)·0.9)·0.7 + fbm(dir·11 + …)·0.3
glow   = exp(−3h / (reach·(0.35 + 1.3·flames)))
color += mix(gold, red, h) · (glow·(0.6 + 1.4·flames) + rim(h)) · (1 + snare)

// prominences: 48 steps through a bounding sphere
for each step p (rotated into the star frame):
    d = min over 5 arcs of |( |local.xy| − height, local.z )| − thickness(angle)
    density += (exp(−70d) + 0.08·exp(−12d)) · Δt
color += hotPink · density
Tunables: render scalesurfacecoronareachprominencessnare flareorbit speed

ASTEROID CHASE
06

Asteroids · instancing and shadows

The path is built from the field: every waypoint hides in a rock's shadow.

The first scene of the mesh renderer. Eight rock variants are built at start-up — icospheres displaced by noise, with craters carved as bowls and raised rims — in two levels of detail. Thousands of instances share one storage buffer and are drawn with a handful of calls.

  • A path made for shadows: big "hero" rocks are placed first; each waypoint sits behind its rock along the light direction, so the rock is between ship and star when the ship skims past.
  • Chase camera: the same path, a fraction of a second behind — it always seems to be catching up.
  • Cascaded shadow maps: a tight cascade around the ship, a wide one over the field, snapped to texels, sampled with a rotated 12-tap Poisson disc.
  • Light shafts are a radial blur of the sky mask toward the star; the lens flare fades with the star's visibility.
// field (rebuilt only when parameters change)
every ~70 units along z:  heroRock = random(size 6..13)
    waypoint = rock − lightDir · (rock.size + pass) / |lightDir.xy|
path = HermiteSpline(waypoints);  push heroes clear of path and camera
background rocks: outside corridor(path), uniform over annulus area

// each frame (CPU)
ship   = pose(path, speed·t);    bank ∝ lateral acceleration
camera = pose(path, speed·(t − lag)) + up·h − forward·b
for each rock: cull vs frustum and both cascades; LOD by distance
upload all instances to one SSBO;  draw per (variant, LOD) with baseInstance

// rock.frag
height = Σ valueNoise(objectPos·fᵢ)·aᵢ        // sticks to the rotating rock
N      = perturb(normal, dFdx/dFdy(worldPos), dFdx/dFdy(height))
color  = albedo · (sun · max(N·L, 0) · PCF₁₂(shadowMap))
       + albedo · ambient · cold + rim · max(−V·L, 0)

// shafts (½ res): march 48 steps toward the star's screen position
sum += isSky(depth(p)) · glow(|p − starUV|) · decayᵏ

Ringed giant

RINGED GIANT
07

Rings · raytracing meets rasterization

The planet and the ring disc are raytraced analytically in one pass, which also writes depth. Ice chunks near the camera are rasterized afterwards and depth-tested against it. Ring opacity above 0.5 writes depth, an approximation that lets dense parts of the sheet occlude chunks.

  • Ring profile: radial opacity built from a base curve, fine ringlets and two gaps.
  • Shadows both ways: rings in the planet's shadow cylinder go dark; points on the planet test where their ray to the sun crosses the ring plane.
  • Back side: seen from below, rings glow by transmission — thin parts brightest, toward the sun.
  • Hand-off: the sheet fades out within 70 units; there, chunks are generated on a grid of cells around the camera, with the same radial density.
for each pixel:
    tPlanet = raySphere(ro, rd, R);   tRing = −ro.y / rd.y
    if tPlanet hit:
        p = hit;  color = bands(p) · sun · max(n·L, 0) · ringShadow(p)
        // ringShadow: s = −p.y/L.y; 1 − opacity(|(p + L·s).xz|)·0.9
    if tRing > 0 and (planet missed or tRing < tPlanet):
        r = |hit.xz|;  α = opacity(r) · smoothstep(nearFade·0.35, nearFade, tRing)
        face = sameSideAsSun ? albedo·sun·(0.25 + 0.75|L.y|)
                             : albedo·sun·(1 − α)·forwardScatter(rd·L)
        color = mix(color, face · planetShadow(hit), α)
    depth = planet hit ? projectedDepth(tPlanet) : 1
    if ring is in front and α > 0.5: depth = projectedDepth(tRing)
    gl_FragDepth = depth

// CPU, each frame near the ring plane
for each cell (2.5 units) within 70 of the camera:
    p = cellCenter + jitter(hash);  y = (hash − ½)·2.4
    if hash < opacity(|p.xz|)·1.1 and clear of camera path:
        addInstance(p, size(hash), spin(hash, t))
Tunables: sun azimuthsun elevationsun intensitychunk densityfocal

Canyon run

CANYON RUN
08

Canyon · heightfield raymarching

A heightfield traced per pixel, a mesh drawn on top, one shared depth.

The terrain is a function h(x, z) marched per pixel at reduced resolution, writing depth. The result is upscaled together with its depth, and the fighter mesh is then drawn at full resolution and depth-tested against it — crisp ship, affordable terrain.

  • Shape: mesas from noise, carved by a winding canyon whose walls are mapped through a terrace function for flat ledges and steep rises.
  • Material: strata colours by height, sand on flat ground, dark streaks on cliffs.
  • Shadows: soft heightfield shadows from the low sun, plus the fighter's own shadow, an analytic ellipsoid test.
  • Volumetric dust low in the canyon; each sample probes twice toward the sun to know if it is lit.
  • The fighter is shaded with the same terrain shadow function, so it flies in and out of the cliffs' shade.
h(x, z):
    mesa = 70 + noise(x,z)·40 + noise(…)·12
    d    = |x − center(z)| + erosion(x,z)
    s    = clamp((d − 0.35·w(z)) / (0.9·w(z)), 0, 1)
    return mix(floorNoise, mesa, terrace(s))   // (⌊5s⌋ + smoothstep(.55,1,fract 5s))/5

// march: conservative steps for steep cliffs, then bisection
repeat: Δ = p.y − h(p.xz);  if Δ < 0.002t break;  t += max(0.3Δ, ε(t))
5 × bisect(previous t, t)

n     = normalFromCentralDifferences(h)
sun   = max(n·L, 0) · softShadow(p, L) · shipShadow(p)
// softShadow: march toward L, visibility = min(10·Δ/t)
color = strata(p.y, n) · (sun·sunColor + sky·(0.5 + 0.5 n.y)·depthAO + bounce)
color = mix(color, haze, 1 − e^(−0.0015 t))

// dust: 16 jittered steps, density = e^(−y/12) · noise3D(p + wind)
lit = Π clamp((q.y − h(q.xz))·0.2) for q = p + L·{12, 40}
L  += T · (sun·lit·HG + sky) · density · Δt

FLEET JUMP-IN
09

Fleet · timing on the beat

Twelve arrivals, one every other beat.

An almost pure reuse scene: the dreadnought's procedural mesh, hull shader and planet sky, twelve instances and two shadow cascades. What makes it is timing: each arrival is scheduled on a beat of the music.

  • A ship approaches from thousands of units behind its slot, braking exponentially — fast enough to read as a jump.
  • During the first fraction of a second the mesh is stretched along its length, the classic hyperspace exit.
  • Streaks and flashes are drawn in one fullscreen pass: ship positions are projected on the CPU and passed as uniform arrays; the shader sums a glowing segment and a flare per ship.
beat = 60 / bpm
for ship i in 0..11:
    s = t − (firstBeat + i·everyBeats)·beat
    if s < 0: continue                      // not yet arrived
    position  = slot[i] + drift(t) − (0, 0, 2000·e^(−7s))
    stretchZ  = 1 + 25·e^(−10s)
    instances += translate(position) · scale(1, 1, stretchZ)
    streak[i] = (project(tail), project(head)),  intensity e^(−6s)
    flash[i]  = project(head),                   intensity e^(−4s)

shadowPasses(instances);  sky(planet);  hulls(instances)

// flashes.frag, added on top
for i: color += blue · streak[i].intensity · glow(distToSegment(pixel))
        color += white · flash[i].intensity · (radialGlow + horizontalFlare)

Dreadnought

DREADNOUGHT
10

Dreadnought · a procedural city

An original wedge-shaped capital ship, built entirely by code. Large forms come from lofts — polygon cross-sections joined along z. Detail comes from layers of rules that read the shape's own height functions.

  • The city: a grid over the decks; noise defines districts and plazas; a block is placed only where its four footprint corners share one level, so terraces stay clean; some are stacked, a few become towers.
  • Baked contact occlusion: block vertices touching the hull are darkened — a cheap stand-in for ambient occlusion.
  • Hull shader: plates whose size and orientation vary by region, seams and small raised blocks as bump, weathering streaks, a low grazing sun with soft shadows, blue planet bounce, reflections.
  • Cinematography: the ship moves, the camera mostly hangs still; cuts land on bar lines.
// big forms
hull  = loft(hexagon, rings z = −100 … 100, width/height profile)
tiers = 3 × loft(rect, following ridge(z) + lift·k)
+ tower, domes, reactor bulb, engine block with 7 nozzles

// city on the decks
for each cell (1.4 units) on the top surface:
    district = fbm(x·0.045, z·0.045)
    if rand > 0.12 + 0.75·smoothstep(.4, .62, district): continue
    footprint = cell · rand(0.45..0.95)   // long rows in dense districts
    if max(cornerHeights) − min(cornerHeights) > 0.5: continue
    height = 0.25 + 1.6·rand^2.2 · (0.6 + district)  // 3%: tower
    addBox(base = min(corners), occlusion(bottom) = 0.4)
    maybe stack a smaller box
+ rims, turrets, lit windows in noise runs, underside plates, docking bay

// hull.frag
plate = regionVariedRectangles(planarUV(p, n))   // id, distance to seam
N     = perturb(n, seams·0.04 + raisedBlocks(uv))
color = albedo(plate, grime) · (sun·N·L·PCF + planetBounce + ambient)·AO
      + env(reflect) · fresnel + engineGlow / distance²

Supernova

The star dies on the beat: a shock shell of hot gas and cooling filaments races outward, a pulsar sweeping at its heart.
SUPERNOVA
11

Supernova · an expanding volume

A three-act scene timed to the music: the giant grows unstable, collapses in the last second, and the flash lands exactly on beat 16. The shell is then raymarched at half resolution.

  • Approximately self-similar expansion: noise uses p / max(R, 1), stabilizing the start. It grows with R above 1, but thickness 0.22R + 1 changes the shell's relative shape.
  • Wrinkled front: the shock radius varies with direction — Rayleigh–Taylor-like fingers.
  • Temperature: blue-white at the front, cooling to hydrogen pink and oxygen teal filaments (cell noise) inside.
  • An equatorial ring flares, a pulsar's beams sweep the gas, 4000 debris streaks ride outward; the camera shakes and pulls back.
flash at t₀ = duration/3;   s = t − t₀

Wormhole · two skies, one lens

One number — the impact parameter — decides which universe a ray sees.

A fully analytic lens, cheap enough for full resolution. Each ray is classified by its impact parameter b, its closest distance to the mouth's center.

  • Through the mouth (b < R): the ray exits into the other universe, rotated more and more toward the rim, so the disc shows the whole far sky with multiple images at its edge.
  • Outside: the ray is bent around the mouth, lensing our own sky — including the pink remnant of the supernova we just left.
  • The other sky holds a face-on spiral galaxy: logarithmic-spiral arms in a gnomonic projection — the next destination.
  • Gas vortex: a noise shell rotating at one angular speed, with a stronger static angular twist near the mouth. The tunnel wraps seamlessly using the noise volume's periodicity.

Galaxy · density waves

No gravity is simulated: the arms are ellipses that twist.

Spiral arms without simulating gravity. Every star moves on an ellipse whose orientation twists with its size; where neighbouring ellipses crowd together, two arms appear — a density wave. Stars stream through the arms while the pattern itself turns slowly.

  • Each star is one vertex (GL_POINTS) whose attributes all come from integer PCG hashes of its id — exact for millions of ids.
  • Point size shrinks with distance; dividing brightness by size reduces its growth. This is not energy conservation: the sprite's area grows as size², so total light still grows roughly with size.
  • Gas puffs are added; dust puffs trail the arms and are multiplied into the image (dst ·= 1 − src), carving dark lanes.
  • A background pass adds disc haze where the ray crosses the galactic plane, and a flattened core glow.

BLACK HOLE
14

Black hole · bending light

Every camera ray is integrated as a light path around a Schwarzschild black hole using the classic approximation a = −1.5 h² x / r⁵, where h is the ray's angular momentum. No special cases are written for the effects: they emerge from the integration.

  • Shadow: captured rays receive no background sky; disk and jet emission gathered before capture remains visible.
  • The Interstellar arc: rays bent over the top hit the far side of the disk.
  • Photon ring: rays that orbit and cross the disk several times.
  • Disk: thin-disk temperature profile; turbulence in a co-rotating frame with Keplerian speeds that wind it into spirals; hot spots flaring on the snare.
  • Relativity: Doppler factor from the orbital velocity and gravitational redshift — the approaching side is brighter and bluer. A doppler knob blends it from cinematic-symmetric to physical.
pos = camera;  dir = rd;  h² = |pos × dir|²
color = 0;  α = 0;  captured = false
repeat up to N steps:
    r = |pos|
    if r < 1: captured = true; break       // retain gathered light
    if escaping: break
    dt   = clamp(0.12·(r − 1), 0.012, 1.5)
    dir += −1.5 · h² · pos / r⁵ · lensing · dt
    prev = pos;  pos += dir · dt

    if sign(prev.y) ≠ sign(pos.y):            // crossed the disk plane
        p = lerp to y = 0;  r = |p.xz|
        if inner < r < outer:
            T    = (r₀/r)^¾ · (1 − √(r₀/r))^¼ / 0.488
            φ    = atan(p.z, p.x) − r^(−1.5)·speed·t   // Keplerian
            turb = fbm(cos/sin(φ + 2.5 ln r)·2, r·2.5)
            β    = √(0.5/(r − 1));  δ = 1/(γ(1 − β·toObserver))
            g    = √(1 − 1/r);      shift = mix(1, δ·g, doppler)
            c    = blackbody(T·shift·temp) · T² · shift³ · (0.4 + 1.6·turb + spots)
            color += (1 − α)·c·a;  α += (1 − α)·a   // front to back
    jets(pos)                                    // optional polar glow
if not captured and α < 0.99:
    color += (1 − α) · lensedBackground(normalize(dir))

A · Techniques appendix

The common toolbox

Noise, everywhere

Float hashes ("hash without sine") drive most per-pixel effects; integer PCG hashes take over when ids reach the millions. Value noise interpolates hashed lattice corners with a smooth curve; fbm sums octaves at doubling frequency and halving amplitude. Worley (cellular) noise measures the distance to the nearest random feature point — inverted, it makes billows and filaments.

The noise volume

Volumetric scenes need hundreds of noise lookups per pixel. A compute shader bakes a 128³ RG8 texture once: every octave uses a period that divides the volume, hashing coordinates modulo the period, so the texture tiles seamlessly in all three directions and hardware trilinear filtering does the rest.

Integrating a volume

The pillars integrate emission and in-scattered light S analytically within each step, assuming constant extinction σ and source S. This removes the plain sum's brightness bias for a uniform medium; varying density, lighting and shadows still introduce step-count-dependent sampling error.

Canyon dust, supernova gas and wormhole gas instead use a simpler T · source · Δt sum, followed by exponential attenuation. These four passes jitter the start per pixel to turn banding into fine grain.

L += T · S · (1 − e^(−σΔt)) / σ
T ·= e^(−σΔt)
HG(cosθ, g) = (1 − g²) / (1 + g² − 2g·cosθ)^1.5    // isotropic = 1

Shadows

Directional lights use cascaded shadow maps: each cascade is an orthographic box around a sphere, extended toward the light to catch distant occluders, and snapped to whole texels so shadows don't shimmer as the camera moves. Lookups offset the position along the normal and average 12 Poisson taps rotated per pixel.

Bump mapping without tangents

Procedural meshes have no UVs. Surface detail perturbs the normal using screen-space derivatives of the world position and of a height field (Mikkelsen's method), so any noise can become relief.

Post-processing

Scenes output linear HDR. Bloom thresholds softly, downsamples with a 13-tap filter (with a Karis average on the first pass against flickering highlights) and upsamples with a tent filter into a 6-level chain. Chromatic aberration grows toward the corners; ACES compresses highlights; grain dithers away banding.

shadow(p) = mean over 12 taps of
            compare(cascadeMatrix · (p + n·1.5 texel), rotate(φ_pixel)·poisson_k)
N' = normalize(|det|·N − strength · sign(det)·(dh/dx·r₁ + dh/dy·r₂))

A · Techniques appendix

Sound, time and procedure

A song made of code

The placeholder soundtrack is a four-channel ProTracker module assembled byte by byte in memory: a kick from a pitch-swept sine, a snare and hats from filtered noise, a single-cycle saw bass and a pulse lead playing arpeggios. libopenmpt plays it with Amiga-style resampling.

Sync without callbacks

Instead of reacting to audio events, the demo scans the module once at load time — rendering it silently at 8 kHz and noting every row change and note-on with a 2 ms resolution. Scenes query the resulting table by time, which keeps sync exact while scrubbing, pausing or looping.

scan(module):
    while render(16 frames at 8 kHz) > 0:
        if (order, row) changed:
            rows += (time, order, row)
            for channel: if noteOn: hits[channel] += time,
                                    hits[instrument] += time
sinceInstrument(i, t) = t − last(hits[i] ≤ t)
pulse = e^(−since · decay)

Geometry from rules

Meshes are assembled from a few generators: subdivided icospheres (rocks, domes, balls), lofts of polygon cross-sections (hulls, wings, nozzles, boxes), and appended copies with transforms that flip winding when mirrored. Faces are oriented outward automatically, and flat shading duplicates vertices per face for crisp hard-surface edges.

Transitions as files

A transition is any shader in shaders/transitions/ that receives the outgoing and incoming frames and a progress value: crossfade, an HDR white flash peaking on the cut, a slanted wipe with a glowing edge, a pixel dissolve, a digital glitch. Adding one is adding a file.

One rule

Everything in this book obeys the same contract: an image is a function of time. It is what lets a five-minute demo be edited live, scrubbed like a video, and photographed beat by beat for these pages.
